Two-Phase Commit for the Agentic Age

Agent2Agent (A2A), the Model Context Protocol (MCP), and the Agent Payments Protocol (AP2) are new wire formats wrapped around forty-year-old distributed-systems theory. Here's the lineage.

Every few years the infrastructure world rediscovers a problem the database and distributed-systems communities solved decades ago, gives it a new acronym, and ships it as if it were novel. That's not a criticism — it's how engineering works. But it's worth naming the lineage before we mistake the wrapper for the invention. This is that exercise, applied to the current stack of agent protocols: Agent2Agent (A2A), the Model Context Protocol (MCP), and the Agent Payments Protocol (AP2).

Strip the branding and you get three familiar problems: how do independent parties discover and delegate work to each other (solved, partially, in 1980); how do they describe what they mean when they talk (solved, partially, in the 1990s); and how do they agree on an outcome — and recover when they don't — when one party's judgment is a probabilistic language model instead of deterministic code (not solved, but not new either).

Begin

The Auction Nobody Remembers

Contract Net Protocol (CNP) — Reid G. Smith, 1980

Before there was an A2A Agent Card advertising a service's skills, there was the Contract Net Protocol: a manager node announces a task, eligible nodes submit bids describing how well they can do it, the manager awards the contract to the best bid, and everyone else stands down. No central scheduler, no shared memory — just an announce/bid/award cycle between independent nodes.

A2A's task delegation flow is the same shape with better tooling. An orchestrating agent needs work done; it queries an Agent Card (a machine-readable description of what an agent can do, served at a well-known address) instead of a bid message, and hands off a Task instead of awarding a contract. The auction became a lookup. The underlying coordination problem — "who among many independent, mutually distrusting parties should do this work" — is unchanged.

Prepare

Teaching Agents to Speak

FIPA-ACL, built on KQML and speech-act theory — 1990s

Knowing an agent exists is not the same as being able to talk to it. The Foundation for Intelligent Physical Agents' Agent Communication Language (FIPA-ACL) — itself built on the earlier Knowledge Query and Manipulation Language (KQML) — tackled that in the 1990s by borrowing from linguistics. Its messages aren't raw data; they're performatives, borrowed from speech-act theory (Austin, Searle): inform, request, cfp (call for proposal), propose, accept-proposal, reject-proposal. The performative tells you what the message is doing; a shared ontology tells you what its content means, so two agents built by different teams don't just parse each other's bytes, they agree on semantics.

An A2A Agent Card's declared skills, input/output schemas, and authentication requirements are doing exactly this job — establishing a shared vocabulary before a Task begins — with JSON Schema standing in for FIPA's ontologies. FIPA even formalized the Contract Net exchange above as fipa-contract-net, a named interaction protocol built entirely out of its own performatives. The auction and the language were fused thirty years before Google fused them again.

Vote

The Commit Problem

Two-Phase Commit (2PC) — Jim Gray, ~1978

Discovery and language get two agents talking. They don't get two agents to agree on an irreversible action — like spending someone's money — atomically. That's a transaction processing problem, and it was solved for distributed databases before either of us started our careers: a coordinator asks every participant to prepare and vote, and only issues commit if every vote is yes. One dissent, and everyone rolls back. Nothing partially happens.

AP2 runs the identical protocol under a different name. An Intent Mandate — a scoped, user-signed statement of what's wanted — is the prepare phase. A Cart Mandate, produced by the merchant-side agent and checked against the Intent by the buyer-side agent, is the participant vote. A Payment Mandate is the commit. Each Mandate is a W3C Verifiable Credential (VC) — a cryptographically signed, tamper-evident digital claim — so the "vote" is a signature, not a network message, but the state machine is 2PC's, unchanged: prepare, vote, commit-or-abort.

The interesting part was never how to move money. It was always how to get independent parties to agree, atomically, before doing something you can't take back.
Compensate

When the Vote Fails

Saga Pattern — Garcia-Molina & Salem, 1987

2PC assumes a transaction is short enough to hold locks across every participant until everyone votes. Agent workflows rarely are — a delegated task can run for minutes, call three other agents, and involve a human approval step in the middle. Locking that whole span isn't practical, and it's exactly the problem the Saga pattern was built for: instead of one atomic transaction, run a sequence of local transactions, and give every step a compensating action to undo it if a later step fails.

This — not any cryptographic guarantee — is the honest answer to "agents are probabilistic, isn't that risky." You cannot make a language model's judgment deterministic by wrapping it in a stronger protocol. What you can do is make every step it takes reversible: a Cart Mandate the buyer-agent shouldn't have accepted gets cancelled, a Payment Mandate gets refunded, a downstream booking gets a compensating cancellation. AP2's mandate chain is set up to support exactly this — the risk isn't eliminated, it's bounded and made recoverable, which is what Sagas have always done for fallible distributed workflows.

Quorum

Trusting an Unreliable Voice

Byzantine Fault Tolerance (BFT) — Lamport, Shostak & Pease, 1982

The Byzantine Generals Problem asked how a distributed system reaches correct agreement when some participants might be faulty or actively lying, not just offline. The answer — quorum-based consensus, where you trust the agreement of a majority over any single voice — predates blockchain by decades; it's the reason blockchain's consensus layers work at all, not something blockchain invented.

It's also the honest framing for probabilistic agents. A single LLM-driven agent's output is, at best, a Byzantine node with good intentions and unreliable judgment. Requiring quorum attestation — a second verifier agent, a rules-based policy check, or a human-in-the-loop sign-off — before a Mandate finalizes is a direct application of 1982's answer to 2026's problem: don't trust one voice, trust agreement among several independent ones.

Use Case: Sourcing a Part, Automatically

A procurement agent needs a replacement part for a warehouse conveyor, under $400, deliverable within a week. Walking it through the stack above:

BEGIN

The procurement agent broadcasts a call-for-proposal to three supplier agents it discovered via their Agent Cards — the Contract Net auction, running over A2A.

PREPARE

Each supplier agent replies with a FIPA-style propose performative: part, price, lead time — structured against a shared schema so "lead time" means the same thing to all four agents.

VOTE

The winning bid becomes a Cart Mandate. The procurement agent checks it against its Intent Mandate (budget, deadline) — the 2PC prepare/vote step, now a signature check instead of a network round-trip.

QUORUM

Because the order exceeds a policy threshold, a second verifier agent independently re-checks the Cart against the Intent before sign-off — Byzantine-style: don't commit on one agent's word alone.

COMMIT

Payment Mandate signs, funds move, the deal settles.

COMPENSATE

Supplier cancels the next morning. No re-negotiation from scratch — the Saga's compensating action fires: refund the Payment Mandate, reopen the Cart, restart the auction among the two remaining bidders.

None of this makes A2A, MCP, or AP2 less useful — standardizing forty years of scattered theory into one interoperable, cryptographically verifiable stack is genuinely hard, valuable work. It just means the risk conversation should be about what's actually new: not "can we trust the wire protocol," which was solved before most of us were writing code, but "can we bound and recover from a probabilistic agent's bad judgment," which is the one piece none of 1978, 1980, 1982, or 1987 anticipated.

Glossary

A2A
Agent2Agent Protocol — Google's open standard for agent-to-agent coordination and task delegation.
MCP
Model Context Protocol — Anthropic's open standard for connecting agents to tools and data sources.
AP2
Agent Payments Protocol — Google's open standard for agent-initiated, cryptographically authorized payments.
CNP
Contract Net Protocol — a 1980 task-allocation protocol based on announce/bid/award.
FIPA-ACL
Foundation for Intelligent Physical Agents' Agent Communication Language — a 1990s standard for structuring agent messages around speech acts.
KQML
Knowledge Query and Manipulation Language — an earlier agent-messaging language FIPA-ACL built on.
2PC
Two-Phase Commit — a distributed-transaction protocol ensuring all parties commit or none do.
BFT
Byzantine Fault Tolerance — consensus that holds even when some participants are faulty or dishonest.
VC
Verifiable Credential — a W3C standard for cryptographically signed, tamper-evident digital claims.
